以下の手順で、`@.claude/rules/git-workflow.md` のコミットメッセージ規約に従いコミットを作成してください。

## 現在の git 状態

**ステージ済み変更:**
```
!`git diff --cached --stat`
```

**差分詳細:**
```
!`git diff --cached`
```

**直近のコミット（スタイル参考）:**
```
!`git log --oneline -5`
```

## 手順

1. 上記の差分を分析し、変更内容を把握する。変更が複数の独立した関心事（例：新機能とドキュメント更新、バグ修正とリファクタリング）を含む場合は、関心事ごとに分割してコミットする。その場合は `git add` で対象ファイルを選択し、コミットを繰り返す。
2. 以下のフォーマットでコミットメッセージを決定する：

   ```
   <type>(<scope>): <subject>

   <body>（任意：変更理由や補足が必要な場合のみ）

   <footer>（任意：BREAKING CHANGE がある場合のみ）
   ```

   **type の選択基準：**
   | type | 用途 |
   |------|------|
   | `feat` | 新機能の追加 |
   | `fix` | バグ修正 |
   | `docs` | ドキュメントのみの変更 |
   | `style` | コードの意味に影響しない変更（空白・フォーマット等） |
   | `refactor` | バグ修正でも新機能追加でもないコード変更 |
   | `perf` | パフォーマンスを改善するコード変更 |
   | `test` | テストの追加・修正 |
   | `chore` | ビルドプロセスや補助ツール・ライブラリの変更 |

   **subject のルール：**
   - 命令形・現在形（"changed" や "changes" ではなく "change"）
   - 先頭を大文字にしない
   - 末尾にピリオドを付けない

3. ユーザーが引数 `$ARGUMENTS` でヒントを渡した場合はそれを参考にする。

4. コミットメッセージをユーザーに提示し、確認を取った上で `git commit` を実行する。

   ```bash
   git commit -m "<確定したメッセージ>"
   ```

ステージ済みの変更がない場合は、`git status --short` で変更ファイルを確認し、コミット対象として適切なファイルを自分で `git add` してからコミットを進めてください。変更ファイルも存在しない場合のみ、その旨をユーザーに伝えて終了してください。
